# Release notes for 0.2.0

Package version: **0.2.0**.

## Implemented behavior

- Registered agents select their manifest's harness, model, and versioned
  instructions. Task worktrees start at the invoking checkout's HEAD and inherit
  recognized agent configuration, including local changes. Unrelated dirty source
  stays in the invoking checkout.
- The interactive launcher accepts numbered or named agents and a blank automatic
  selection. Its multiline prompt requires a `.` sentinel and a separate
  confirmation code. Scriptable `launch` accepts inline, UTF-8 file or piped
  prompts; `--dry-run --output json` emits a schema 1 preview without a cmux task.
  Non-interactive approval widening requires `--allow-widened-approvals`.
- `task` reports recorded locations and session state; `diff` compares tracked
  work against the launch base and lists untracked files separately. Neither a
  process exit nor a saved session state verifies task completion.
- Interactive task records and prompts live in each task worktree. Headless
  coordination and the scoped task index belong to the primary checkout. Native
  settings, skills, histories, final text, and helper summaries remain native;
  ahu retains bounded outcomes and session references, with unknown locations
  explicitly marked. Old stores remain readable in place without migration;
  legacy resume/dispatch require the original runner or a new assignment.
- `--repo` explicitly selects the checkout; ambient storage selectors are retired.
  Task commands accept typed references, bare IDs, and unique prefixes. Inbox
  payload flags remain literal. Interactive execution supervises the child with
  terminal foreground handover/restoration and records cancellation confirmation.
- `cmux status`, doctor, and launch disclosures share bounded native integration
  inspection. Explicit installation delegates fixed native arguments with native
  confirmations and default user scope. Unknown evidence stays unknown; the
  reviewed OpenCode Feed plugin refuses headless coexistence.
- Git and default cmux resolution use canonical absolute PATH candidates outside
  Git working trees, inspecting candidate ancestry without executing repository
  Git. Empty and relative PATH entries are skipped. Explicit `AHU_CMUX_BIN`
  retains deliberate user-selected command semantics.
- State access refuses static symlink redirection. Startup verifies recorded
  digests and task identity, but mutable local records are not authenticated
  against a writer changing both data and digests. Path checks do not protect
  against concurrent hostile host processes or provide OS isolation.
- Plain sidebar titles and summaries accompany agent/model identity. Terminal
  styling honors explicit color selection, `NO_COLOR`, `TERM=dumb` terminals, and
  redirected stdout. Repository-derived controls are escaped, JSON remains
  unstyled, and knowledge severity columns align in plain and colored output.
- `knowledge lint` checks configured OKF bundles with installed OKF, combines
  validation and lint findings, and applies the configured warning policy.
  Repository knowledge concepts record current invariants with source provenance.
- Rust checks are defined for Ubuntu 24.04 and macOS 14 with pinned Rust 1.96.0.
  A separate dependency workflow uses pinned cargo-deny 0.20.2 and current
  advisories. The [release dependency policy](../dependencies.md) defines required scans,
  maintainer review and scoped exceptions.

See the [reference](../reference.md) for exit codes, JSON fields, prompt transport,
configuration inheritance, and compatibility baselines.

## Validation and limits

The [conformance matrix](../reference.md#conformance-evidence) separates native
artifact inspection, synthetic fixtures, real PTY cases, live cmux plumbing,
and scoped native no-op probes. These do not establish four-harness live
conformance. Installed CLI versions do not expand admitted headless profiles.

The authored OKF bundle is a maintainer check with installed OKF 0.5.0;
ordinary CI uses synthetic validator fixtures and does not install OKF. Workflow
files define checks, not proof of hosted success or branch-protection settings.

The palette uses terminal foreground colors, bold, and dim text without setting a
background. Labels retain meaning without color. Representative 80-column
agent/error output was inspected in browser-rendered light/dark reference
palettes; this was not a native-terminal theme test. Dim hints and colors still
depend on the terminal's palette. Mermaid structure checks do not establish
rendered appearance.

Worktrees separate Git changes; they are not an operating-system sandbox.
Harness settings govern runtime access and approvals. Delegation instructions
are prompt text, and inventory reports its visibility gaps. No fresh provider
session is implied by documentation or synthetic tests.
