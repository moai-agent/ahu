# 0.2.0 preparation notes

**Unreleased.** The package version is prepared as 0.2.0. These notes describe
the local implementation; no release publication or hosted CI success is claimed.

## Implemented behavior

- Registered agents select their manifest's harness, model and versioned
  instructions. Task worktrees start at the invoking checkout's HEAD and inherit
  recognized agent configuration, including local changes. Unrelated dirty source
  stays in the invoking checkout.
- The interactive launcher accepts numbered or named agents and a blank automatic
  selection. Its multiline prompt requires a `.` sentinel and a separate
  confirmation code. Scriptable `launch` accepts inline, UTF-8 file or piped
  prompts; `--dry-run --output json` emits a schema 1 preview without a cmux task.
  Non-interactive approval widening requires `--allow-widened-approvals`.
- `task` reports recorded locations and session state; `diff` compares tracked
  work against the launch base and lists untracked files separately. Neither a
  process exit nor a saved session state verifies task completion.
- Plain sidebar titles and summaries accompany agent/model identity. Terminal
  styling honors explicit color selection, `NO_COLOR`, dumb terminals and
  redirected stdout. Repository-derived controls are escaped, JSON remains
  unstyled, and knowledge severity columns align in plain and colored output.
- `knowledge lint` checks configured OKF bundles with installed OKF, combines
  validation and lint findings, and applies the configured warning policy.
  Repository knowledge concepts record current invariants with source provenance.
- Rust checks are defined for Ubuntu 24.04 and macOS 14 with pinned Rust 1.96.0.
  A separate dependency workflow uses pinned cargo-deny 0.20.2 and current
  advisories. The [dependency policy](../dependencies.md) remains a proposal
  awaiting maintainer approval.

See the [reference](../reference.md) for exit codes, JSON fields, prompt transport,
configuration inheritance and compatibility baselines.

## Validation and limits

Local validation passed against the integrated 0.2.0 checkout:

- Skill-copy consistency, Rust formatting, whitespace checks and local
  documentation link/provenance paths.
- Installed OKF 0.5.0 `validate`, `lint`, and the configured ahu JSON check:
  zero errors and zero warnings.
- Locked build, all-target Clippy with warnings denied, and the full ordinary
  Rust suite: 248 test functions reported passing, including six live-only
  functions that return early without opt-in. The separate opt-in cmux run
  passed all eight functions, including the six live scenarios. Rust doctests
  passed with zero examples.
- Both workflows passed actionlint. The online dependency scan passed advisories,
  bans, licenses and sources, with the expected duplicate `winnow` warning.
  Controlled formatting, skill-copy and dependency-policy violations failed
  their local checks as intended.
- Built CLI version/help/agent listing and a named JSON launch preview with
  `executed: false`; no provider session was launched.

These are local results; live cmux fixtures use stand-in harnesses. Hosted workflow execution,
required-check settings, dependency policy approval and release publication
remain separate from local checks. The authored OKF bundle is a
maintainer check with installed OKF 0.5.0; ordinary CI uses synthetic validator
fixtures and does not install OKF.

The palette uses terminal foreground colors, bold and dim text without setting a
background. Labels retain meaning without color. This code-level review does not
establish subjective light/dark legibility; dim hints depend on the terminal's
palette. Mermaid structure checks do not establish rendered appearance.

Worktrees separate Git changes; they are not an operating-system sandbox.
Harness settings govern runtime access and approvals. Delegation instructions
are prompt text, and inventory reports its visibility gaps. No fresh provider
session is implied by documentation or synthetic tests.
