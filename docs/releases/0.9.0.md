# Release notes for 0.9.0

Version **0.9.0** is a prerelease candidate focused on routing work by verified
provider capacity and on reporting headless completion and failure recovery more
precisely. It is prepared from base commit `08bf818`. Publication and validation
evidence accompany the GitHub release; these notes are not proof of a published
tag.

## Provider rate limits

`ahu auth budget [--output json]` and the MCP tool `ahu_auth_budget` report the
active project profile's verified provider rate-limit windows. Supported windows
expose `used_percent`, `remaining_percent`, `window_duration_minutes`, and the
provider's reset timestamp. The view never contains account identifiers,
credentials, prompts, or raw provider responses.

```sh
ahu auth budget
ahu auth budget --output json
```

Codex is the only provider with a supported machine-readable view. ahu requests
`account/read` and `account/rateLimits/read` in one native app-server session and
verifies that account against the active profile fingerprint; a mismatch fails
the command rather than returning capacity for an unverified account. The
`claude-code`, `antigravity`, and `ollama` rows report `unsupported`,
`not_bound`, or `not_configured`. OpenCode has no row at all.

These are rate-limit percentages and reset periods, not token counts, monthly
credits, dollar costs, or a per-agent allocation. Agents sharing a provider
account share its windows. Reading the view is an explicit request: no binding,
readiness, launch, or resume path probes quota, and ahu does not estimate
capacity from run telemetry, read a terminal display, or send an inference
request.

## Capacity-aware delegation candidates

`ahu_auth_budget` accepts an optional `minimum_remaining_percent` between 0 and
100 and returns a `routing.candidates` list matching registered agents to their
harness windows. A candidate is `eligible` only when every reported window
exceeds zero and meets the threshold; otherwise it is `below_threshold` or
`unknown`. Unknown provider capacity is never eligible.

Eligibility is a rate-limit filter alone. It does not compare token or dollar
cost, confirm model availability, or reserve shared capacity, so a second agent
routed to an eligible account still competes for the same windows. The tool's
name and outcome join ordinary MCP telemetry; its arguments and result values
are not exported to OTel.

## Headless completion and recovery

Headless results and their `task`/`result` views separate two questions that
were previously reported together:

- `root_completion` records the root harness terminal event and the process exit
  code.
- `native_completeness` records observed helper lifecycle coverage.

A harness whose helper stream is unsupported leaves helper completion unknown.
That is not evidence that the root result was missing, and it does not prove that
no helpers ran.

A `supervisor_error` attempt now reports a bounded `failure_phase` and
`failure_code` with explicit recovery guidance. ahu refuses to resume such an
attempt automatically: preserve the attempt and worktree, inspect the recorded
phase and code and the worktree diff, determine whether native work ran, and
submit a new registered assignment if more work is needed. Replaying the attempt
is not offered because an uncertain attempt may already have changed native
state.

## Harness compatibility

Claude Code 2.1.289 joins 2.1.283 and 2.1.288 as a reviewed headless invocation
profile receiving `--settings '{"disableAllHooks":true}'`. The profile was
checked against the installed native help, vendor hook controls, and a loopback
model fixture: user, project, and local SessionStart, UserPromptSubmit, and Stop
hooks ran in the control case and were suppressed by the invocation setting. The
requested model and a direct user MCP server remained available. These synthetic
checks do not extend Claude's authenticated headless verification records.

The Antigravity identity probe now sets `NO_COLOR=1` for its bounded startup
capture, because terminal color escape sequences split the account email apart
and defeated extraction. Startup parsing moved into a separately testable step,
and unit tests cover account extraction, workspace extraction, and the refusal
of an API-key startup that exposes no user principal to bind.

This removes color escapes as a parsing obstacle; it does not make Antigravity
readiness available on every installed CLI. The probe still waits a bounded 12
seconds for a recognizable account line and reports `identity: "unavailable"`
when none arrives. A local check against Antigravity CLI 1.2.16 still timed out,
so that pair's readiness remains unavailable there and its launch-time checks
still apply. Why that startup produced no account line ahu could read within the
window is not established, and the parser tests do not answer it. Treat
Antigravity readiness as a pair you verify with
`ahu auth readiness --harness antigravity` rather than one this change fixed.

## Continuous integration

The optional live cmux job probes for a reachable cmux before it installs Rust,
and skips with a visible notice when the runner provides none. If
cmux disappears after a successful probe, the job fails rather than passing a
probe it never ran. A missing optional terminal integration is never reported as
a live pass.

## Evidence and limitations

The release checks require whole-project line coverage strictly greater than 90%,
at least 95% for both the eval/OTel and MCP/OTel code groups, security review,
package boundary checks, and green hosted checks. Live MCP invocations and
collector observations are recorded separately for each exercised harness and
execution mode.

The rate-limit view is read at request time and can be stale by the moment work
is delegated. Synthetic protocol and configuration fixtures verify adapter and
isolation behavior, not live provider compatibility, and an interactive result
does not establish headless support. Native account mismatches and unresolved
integration controls remain blockers for their affected modes. See the release's
verification summary for the exact tested revisions, results, unavailable modes,
and remaining follow-up work.
