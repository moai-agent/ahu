# Release notes for 0.8.0

Version **0.8.0** is a prerelease focused on measuring agent tool use and adding
local typed decisions. Publication and validation evidence accompany the GitHub
release.

## Typed decisions on your machine

The provider-neutral `ahu_typed_decide` MCP tool can use Ollama's native
`/v1/systemone` API with a local decision model. TypeSafe Jev and the generic
local adapter remain available. Choice, score, probability, and batch requests
keep the same portable tool contract.

Native Ollama requires version 0.35 or newer and a decision model such as
`nimble` or `tev1:0.8b`. Select it in the MCP server environment:

```sh
ollama pull nimble
export AHU_OLLAMA_MODEL=nimble
ahu mcp serve
```

The native endpoint is loopback-only. Explicit cloud model names and credentials
in URLs are refused; the transport does not follow redirects or use proxies. Requests and responses have
size and time bounds. Local inference needs no TypeSafe API key. The default
hosted provider still reads `TYPESAFE_API_KEY` from the MCP server environment
or the primary checkout's private `.env`.

See [typed decisions](../typed-decisions.md) for setup, data handling, metadata,
and provider selection. Local inference working successfully does not establish
an agent-level speed or token improvement: compare quality, complete workflow
time, native usage, and separate decision-provider usage on matched cases.

## Observe and constrain tool use

Eval records add bounded trajectory measurements from supported native event
streams: steps, tool calls, explicit failures, repetitions, and later successful
tool completions. Reports show source and coverage alongside each measurement.
No prompts, tool payloads, reasoning text, or raw tool identifiers are retained
in this projection.

Step units differ by harness. Repeated use of a tool does not establish wasted
work, and a successful call after an error does not prove task recovery.
Antigravity trajectory coverage remains unavailable; its existing native usage
and MCP telemetry observations remain separate.

Case front matter can define post-run trajectory budgets. Opt-in CLI guardrails
can make incomplete or excessive trajectory measurements fail CI independently
of answer correctness. See [evaluations](../evaluations.md) for limits, coverage
policies, and reproducible comparisons.

## Readiness and execution

- `ahu doctor` checks account-binding readiness for each registered harness/model
  pair and reports blocked or uncertain readiness without displaying identities.
- Current Codex and Claude Code headless profiles inspect the applicable native
  controls. Unknown hooks, managed policy, and unsupported configuration still
  refuse admission; a profile is not proof that every native setup can launch.
- Codex auto mode explains its workspace write boundary. Tasks that need shared
  Git metadata or protected context changes require coordinator integration.
- Ordinary Git lockfile activity no longer invalidates directory ownership
  evidence. Storage verification still checks directory identity, ownership,
  permissions, canonical paths, and changes to Git locator files.
- Supervisor failures include bounded diagnostic categories without storing
  arbitrary error text or credentials.

## Evidence and limitations

The release checks require whole-project line coverage greater than 90%, at least 95%
for both eval/OTel and MCP/OTel code groups, security review, package boundary
checks, and green hosted checks. Live MCP invocations and collector observations
are recorded separately for each exercised harness and execution mode.

Native account mismatches and unresolved integration controls remain blockers
for their affected modes. Synthetic protocol tests do not establish live
provider compatibility, and an interactive result does not prove headless
support. See the release's verification summary for the exact tested revisions,
results, unavailable modes, and remaining follow-up work.
