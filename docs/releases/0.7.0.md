# Release candidate notes for 0.7.0

Target version: **0.7.0**. This candidate follows the published 0.6.0 prerelease.
Local review and validation are complete. Hosted CI, tagging, and publication
are pending. This file records candidate behavior and the checks performed.

## Accounts and task controls

- Installed harness CLI versions float by default; projects can set exact
  `harness_version_pins`. Verified versions remain compatibility evidence, while
  specialized isolation and native-helper controls retain their version checks.

- Local auth profiles bind fingerprints of native account identities. Opting
  into profiles enables launch/startup checks and resume checks against both
  the active profile and the task's original pin. `ahu auth readiness` reports
  secret-free identity and binding states without a model request. This is
  best-effort protection against an unintended account change, not a credential
  lock, quota check, or guarantee about every provider request. OpenCode's
  Ollama cloud-model check does not verify its effective provider endpoint.
- The task-bound `ahu_request_approval` MCP tool records a cooperative checkpoint.
  Inspect it with `ahu task TASK`, then use `ahu approve TASK` or `ahu reject TASK`.
  Rejection and the 30-minute timeout request cancellation. The tool does not
  intercept shell actions or replace harness permission controls.
- Headless supervision evaluates write-tool events while the harness runs and
  can stop an attempt with `boundary_violation` after observing an absolute
  target outside its worktree. Results retain reported targets for review.
  Detection cannot prevent a completed write or cover shell writes, relative
  paths, unknown tools, or missing events. Final stream observations are checked
  before accepting a successful result.

See [account bindings](../reference.md#local-harness-account-bindings),
[MCP checkpoints](../reference.md#mcp-integration), and
[headless execution](../reference.md#headless-execution) for contracts and limits.

## Measurements and evaluations

- Opt-in local metrics and eval reports distinguish native token observations
  from harness-reported USD. Claude Code result amounts and OpenCode step sums
  retain provenance and observation coverage; missing values remain unavailable.
  These are not invoices or quota measurements. Private telemetry associations
  use explicit task membership and opaque keys in owner-only host state.
- Eval comparisons support advisory skill selection (`none`, `lexical`, or
  `decision`) and separate candidate, selection-provider, and evaluator usage.
  Typed decision grading is opt-in; deterministic answer scores remain separate
  from tool behavior and judge scores. Failed attempts remain in comparisons.
- The project-skill ablation helper prepares a committed control worktree with
  selected project skills removed and a refreshed context lock. Matched eval
  runs compare committed contexts; the helper does not turn off global skills
  or prove which skills a harness loaded.

See [cost and quota coverage](../reference.md#cross-harness-cost-and-quota-coverage)
and [evaluations](../evaluations.md) for reproducible workflows and evidence limits.

## Remaining validation limits

- Hosted Linux and macOS CI has not run for this candidate. Nothing has been
  pushed, tagged, or published during preparation.
- Live headless provider runs were not validated against the installed
  harness configurations. Unresolved native isolation still refuses headless
  admission; successful interactive reviews do not establish headless support.
- The auth-binding module has 43.15% line coverage. Synthetic readiness, profile,
  and resume checks pass, but native sign-in changes across accounts were not
  repeated in this review. Preflight checks remain best effort.
- Live cmux tests use harmless startup commands and synthetic harnesses. They
  verify terminal management, not provider authentication or inference access.

The validation history in the [0.6.0 notes](0.6.0.md) is separate from this
candidate's evidence.
