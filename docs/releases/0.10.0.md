# Release notes for 0.10.0

Version **0.10.0** adds Kiro CLI as an interactive and headless harness, with
registered development, review, and testing agents. The candidate starts from
commit `8197540`. These notes describe its behavior; publication and validation
status are reported separately with the release.

## Kiro CLI support

`ahu setup` detects Kiro CLI, configures the ahu MCP server, and installs bundled
skills in Kiro's native project locations. `ahu kiro` starts an interactive
coordinator. Registered agents pin an exact model, and ahu checks that Kiro
lists that model before launch. Existing native agents remain available through
Kiro's own conventions; ahu does not select or rewrite those profiles.

The repository includes `@dev-kiro`, `@review-kiro`, and `@test-kiro`, each using
`claude-sonnet-4.5`. Development and testing request automatic approvals; review
retains native prompt policy. The review role is an instruction, not enforced
read-only access. Sign-in remains a native Kiro operation.

Kiro V3 versions 2.28.0 and 2.29.0 are admitted for headless fresh execution and
native resume. Shared supervision supplies background execution, timeout,
cancellation, and result inspection. The adapter requires successful MCP startup
and a successful terminal run event. Permission denials, unresolved tool calls,
malformed streams, interrupted runs, and nonzero exits cannot report success.
Replayed history does not determine the current attempt's outcome.

Headless admission inspects bounded native configuration, including agent
profiles, ancestor scopes, and supported MCP fields. Unknown configuration,
hooks, unsupported extensions, and unreviewed CLI versions are refused without
rewriting the user's configuration. This inspection is not a sandbox. Native
helper restrictions remain prompt instructions, and helper completion coverage
remains unknown. See the [Kiro reference](../reference.md#kiro-cli) for commands,
accepted configuration, and remaining boundaries.

## Evaluation and local OpenTelemetry

Kiro evaluation evidence includes observed tool-call lifecycle counts and
prompt-completion metering, with replay and duplicate handling. Reported credits,
elapsed time, and context-window percentages remain separate observations.
Credits are not USD, context usage is not billed tokens, and a prompt completion
is not a model step. Missing measurements remain unknown.

Ahu exports task, parent, root, attempt, and execution-mode attribution through
OpenTelemetry. An optional `ahu.release.id` standard resource attribute freezes
release attribution at launch and carries it through resume and child tasks.
Accounting attributes name their source, aggregation, and partial or unavailable
coverage. Repeated cumulative observations are not summed as independent usage.
These observations do not establish complete release cost or additive totals
across retries and parent-child tasks.

The project's telemetry configuration uses a local OTLP/HTTP collector. Capture
files belong outside Git repositories and must never be published to GitHub.
There is no additional accounting ledger. Native Kiro exports do not yet prove
ahu task-and-attempt correlation; ahu and its MCP server provide their own spans.

## Reliability and security

Changes since 0.9.0 also harden task-record reads, state-path confinement, launch
locking, and cleanup that preserves existing work. Telemetry setup fails closed
when child configuration is invalid, and evaluation receivers authenticate their
local capture requests. Typed decision validation returns errors instead of
panicking on invalid input.

The release requires security review, dependency checks, package inspection,
whole-project line coverage above 90%, and at least 95% line coverage for each
of the eval/OTel and MCP/OTel groups. Fixture tests establish adapter behavior;
they do not establish authenticated provider compatibility. Live observations
are reported separately by harness version, model, and execution mode, with
missing observations and native refusals stated explicitly.
