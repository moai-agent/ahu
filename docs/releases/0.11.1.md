# Release notes for 0.11.1

This patch prepares Rust-only ahu-maintained customer executables. Python remains
allowed for development tests, fixtures and tooling, but is not required to
install or run ahu or the maintained executable plugins.

## External plugin replacements

The coordinated plugin updates are GitHub CLI/tracker 0.1.1 and cmux host 0.2.1.
Both replace their Python implementations with standalone Rust executables.
Their provider operations and wire protocols remain unchanged. GitHub still
requires the native `gh` CLI and its authentication; cmux still requires a working
native cmux session. Neither integration is required for headless or
current-terminal ahu.

Build the plugin for the target operating system and architecture before
computing its package digest. Source directories are no longer directly
installable executable packages. Follow each plugin's updated build and staging
instructions, then review the new version and content pins before updating the
project binding. Installation copies verified content; it never builds source.
Compatibility pins are exact: set `compatibility.ahu` to `"0.11.1"` when using
this CLI version, and retain `host_api: 1`. Before upgrading the CLI or changing
a host binding, finish and remove tasks using the old host with the old CLI and
binding still available. Their frozen host identity must remain usable for
cleanup. Then upgrade the CLI, review and commit the new package/version/content
and compatibility pins, and explicitly update the installed plugins. Companion
skills remain optional text guidance.

The independent text-stats plugin authoring example also uses Rust. Its tests
and the release OTel fixture now stage the compiled executable before install.

The obsolete Python Ollama server example has been removed. Use the existing
Rust-native Ollama decision provider with Ollama 0.35+ and a compatible decision
model; arbitrary chat models are not interchangeable with that API. The generic
decision HTTP contract remains available for independently maintained services.

## Harness coverage and experimental setup

The existing Codex, Claude Code, Antigravity, OpenCode and Kiro adapters are
already Rust and remain available in ordinary builds. This patch does not make
them independently installable harness plugins or change their native approval,
MCP, telemetry or capability limits. See the [runtime inventory](../rust-runtime.md).

The optional `codex-plugin-pilot` build feature uses a Rust launch planner.
It remains experimental: native configuration, event decoding and other harness
responsibilities still live in core. Plain-terminal interactive MCP attribution
and native-service cleanup are unresolved pilot observations. Do not advertise
the pilot as complete Codex extraction or require cmux to work around these gaps.

Setup can list local harness-plugin declarations and prepare an explicitly
selected staged package as a content-pinned binding without activation. Discovery does
not execute code, and preparation does not download, build, install or enable
plugins. No published harness-plugin catalog is provided by this patch.
See the [pilot workflow](../harness-plugin-pilot.md).
